# M0 Task — Device Feasibility Spike

## Goal

Prove on a physical Android phone that CameraX + MediaPipe Hand Landmarker can track
two hands continuously with an aligned skeleton overlay, and measure sustained
performance honestly.

## Allowed change surface

`android/`, `docs/`, `README.md`, `AGENTS.md`, `scripts/`. One application module
only. No feature-contract (`features-v1`) work in M0.

## Invariants

- Hands only, maximum two hands.
- Front camera, 4:3 preview and analysis.
- No frame mirroring before inference.
- Latest-frame backpressure; one frame in flight.
- Every `ImageProxy` closed.
- No INTERNET permission.
- No recognition, no vocabulary, no persistence, no cloud.

## Acceptance criteria

| Gate | Evidence |
|---|---|
| G1 | `:app:assembleDebug` succeeds |
| G2 | Permission granted/denied/permanent/settings-return flows tested on device |
| G3 | Preview works on the physical phone |
| G4 | Analysis receives frames continuously; counters increase |
| G5 | One hand detected |
| G6 | Two hands detected |
| G7 | 21 landmarks per hand exposed |
| G8 | Overlay aligns in 0° and 90° device rotation |
| G9 | Front-camera mirroring aligns and handedness is correct |
| G10 | Rotation does not displace or crash the overlay |
| G11 | No proxy leak or analyzer stall during repeated enter/exit |
| G12 | Ten-minute benchmark completed on the physical phone |
| G13 | Benchmark export (CSV + JSON) and report generated |
| G14 | Limitations documented |

Gates requiring hardware are recorded as `NOT VERIFIED` when no device is available.

## Automated checks

```bash
cd android
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew :app:testDebugUnitTest
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew :app:assembleDebug
```

## Device test protocol

Run once per orientation and once after each lifecycle transition.

1. Fresh install; launch with permission never requested.
2. Deny permission; confirm recovery guidance and that no camera is opened.
3. Deny twice (permanent); confirm Settings recovery action opens app settings and
   returning with permission granted starts the camera.
4. Grant permission; confirm preview.
5. No hand visible → no skeleton, state "No hands".
6. Left hand only → one skeleton; right hand only → one skeleton.
7. Both hands → two skeletons, visually distinct.
8. Move hands quickly → overlay follows without visible lag spikes.
9. Partially occlude fingers → only returned landmarks are drawn.
10. Rotate to landscape and back → overlay stays aligned; no crash.
11. Background the app → camera released; resume → preview restarts.
12. Repeat enter/exit and rotation 10× → no crash, no stall, frame counters recover.
13. Run the ten-minute benchmark; export files; record device, battery and thermal
    data.

## Benchmark export

Long-press the status chip to start. Files are written to the app-private files
directory (`files/benchmark/`), so the documented `run-as` command works without a
storage permission:

```bash
adb exec-out run-as com.hasta.app cat files/benchmark/<run>.json
adb exec-out run-as com.hasta.app cat files/benchmark/<run>.csv
```

Long-press again to stop early. Rotating the device or stopping the camera pipeline
also ends the run. Every run records an `endReason` (`duration_complete`,
`stopped_by_user`, `pipeline_stopped`); only `duration_complete` is a full ten-minute
run.

Do not report benchmark numbers that were not produced by a physical-device run.
